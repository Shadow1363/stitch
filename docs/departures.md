# Departures from Scratch

Stitch keeps Scratch's defaults (480×360 stage, centre origin, y up, direction 90 = right, 1-based lists, floored `mod`, number coercion, division by zero → Infinity, `size` as a percentage, trig in degrees, broadcast restart semantics). Each difference is listed below with its reason. All are **pending owner approval** (D1–D14 since the Phase 1–3 reviews, D15–D18 from Phase 4, D19–D22 from Phase 5, D23 from Phase 7, D24–D31 from Phase 9, D32 from Phase 11).

| # | Scratch | Stitch | Why |
|---|---|---|---|
| D1 | Sprites are silently fenced so part of them stays on stage | No implicit fencing. Sprites can sit fully off-stage, and drawing is clipped to the stage. You fence explicitly with `clamp_to_stage()`, `on_edge()` and `bounce()` | Hidden position edits break float math and confuse coders. Games often spawn sprites off-screen |
| D2 | Positions are rounded to 8 decimals | Full floats. Pixel-art costumes snap to whole pixels at render time only | Deterministic math. Render-only rounding |
| D3 | `if on edge, bounce` uses the pixel-accurate hull | `bounce()` uses the rotated costume's bounding box, reflects direction (keeping Scratch's minimum 0.2 push off the edge), then clamps the sprite back onto the stage. `on_edge()` returns `"left"`/`"right"`/`"top"`/`"bottom"`/`""` (visual edges) so velocity-style code can flip `vx`/`vy` | Cheap, predictable, identical on every renderer |
| D4 | `wait` and `timer` use the wall clock | Simulation time: whole ticks, 60 per second. `wait(s)` waits `max(1, round(s × 60))` ticks | Deterministic and testable; lag never skips a wait |
| D5 | Loops may run several iterations per frame when nothing redraws | Exactly one iteration per tick, except in a `warp function` ("run without screen refresh"), which skips the per-iteration yield. Functions it calls inherit warp. As in Scratch, a warp loop still yields once a tick has run for 500 ms | Predictable timing by default, plus an explicit opt-in for fast loops |
| D6 | Hats fired mid-frame can run in the same frame | Hats fired during a tick start on the next tick | Order doesn't depend on thread position |
| D7 | String `=` ignores case | `==` is case-sensitive. Numeric strings still compare as numbers (`"10" == 10`). `contains` on text is also case-sensitive | Fewer surprises in text code |
| D8 | Key names like `"left arrow"` | `"left"`, `"space"`, `"a"`, `"enter"`, plus `"any"` for `key_down` | Shorter in text |
| D9 | Variables and lists are separate kinds | A variable can hold a list (`var items = [1, 2]`). Lists are shared by reference | One concept; maps to blocks with expression slots |
| D10 | point/distance only target sprites or the mouse | `point_towards(x, y)`, `angle_to(x, y)` and `distance_to(x, y)`, all in Scratch's direction convention. No raw `atan2` | One angle convention everywhere |
| D11 | — | `and`/`or` always return booleans (as Scratch blocks do, unlike Lua) | Matches boolean block slots |
| D12 | — | `return` must be the last statement of a block (as in Lua) | Keeps `return` followed by a newline unambiguous. The return block has no bottom connection, enforcing the same rule |
| D13 | Variables are chosen from a dropdown | Variable and parameter names are typed into text fields on blocks. The Variables category lists declared names | Text and blocks share one namespace with no separate variable registry; a dropdown can come later |
| D14 | Custom blocks have labelled parameter slots | `define` takes comma-separated parameter names, and `call` blocks come from the Functions category with the right number of slots | Keeps one block shape per IR node; a richer editor can come later |
| D15 | "play sound until done" waits for the audio to finish (wall clock) | `play_sound_wait` waits the sound's rendered length in simulation ticks, `max(1, ceil(seconds × 60))`. The sound itself plays on the audio clock | Scripts stay deterministic alongside `wait` and `timer`. If frames drop, the game can trail its sound slightly, but a run always replays the same way |
| D16 | Sounds belong to a sprite; volume is per sprite | Sounds and songs belong to the cart (PICO-8-style banks), and any script plays them by name or 1-based number. `set_volume` / `volume` is one master volume (percent) for sounds and music. Run resets it to 100 | One shared namespace for text code and one place to edit audio. Per-sprite volume can come later |
| D17 | Starting a sound a sprite is already playing restarts it | Each `play_sound` starts a new voice, so repeats overlap, up to 32 voices (then the oldest stops). `stop_sounds` stops them all | Rapid effects such as coins and shots overlap naturally, and no sprite owns sounds |
| D18 | No music engine | `play_music(name)` plays a tracker song (looping if the song is set to loop). One song at a time: starting another replaces it. Stop and Run silence everything, like the green flag | New capability; one-song-at-a-time matches tracker players |
| D19 | No network blocks (TurboWarp extensions fetch directly from the page) | `http_get(url)` / `http_post(url, body)` report the response body and wait for it; `http_status()` gives the sprite's last status (0 = no answer). The editor makes the request, asking once per host per cart, and adds secrets. The stage itself can't fetch (CSP `connect-src 'none'`) | Keeps keys out of carts and out of the sandbox, and lets the user see and refuse every host a cart contacts. See [network.md](network.md) |
| D20 | — | Network replies arrive between ticks and the waiting script resumes on the next one, at its usual place in the order. A run that uses HTTP depends on the network, so it doesn't replay identically (unlike D15) | Simulation time can't wait on the network without freezing every other script |
| D21 | No JSON blocks | `json_get(json, "a.1.b")` follows a dotted path (list indices from 1) and `json_parse(text)` reads JSON. Arrays become lists, objects become dictionaries (D30), `null` and anything missing or invalid read as `""` | JSON maps directly onto Stitch's lists and dictionaries. (Before Phase 9, with no dictionaries, objects stayed as JSON text) |
| D22 | Extensions are JS classes with `getInfo()`, loaded by URL (TurboWarp can run them unsandboxed) | An extension is a JSON manifest plus a script, both saved in the cart. The editor reads only the manifest; the script runs in the sandboxed stage and calls `stitch.define(name, fn)`. Blocks are plain commands and reporters named `<id>_…`, with no hats, menus or custom shapes yet | One registry (the catalog) and a 1:1 text spelling for every block; carts run without fetching code, and extension code never touches the editor |
| D23 | Bright category colours (motion `#4C97FF`, events `#FFBF00`…) with white block text | Darker, more saturated category colours (`BLOCK_COLOURS` in `blocks/src/definitions.ts`). Each keeps white text at WCAG AA (4.5:1), and every pair stays distinguishable under protanopia, deuteranopia and tritanopia simulation. Hues stay close to Scratch's (motion blue, looks purple, control orange), but darker | Scratch's white-on-yellow and white-on-cyan text is about 1.7:1 and 2:1, far below AA. A test checks contrast and distinctness, so a new category can't regress them |
| D24 | Pen blocks draw only where sprites move; the pen layer is a stage-sized bitmap | Besides Scratch's pen, `draw_line`, `draw_rect`/`fill_rect` (two opposite corners), `draw_circle`/`fill_circle` and `draw_text` draw shapes in stage coordinates with the calling sprite's pen. The pen layer sits above the tile map and below sprites; on pixel-filtered stages it's drawn at one texel per stage pixel | Shapes are the common case for HUDs, minimaps and debug drawing. Two corners read the same whichever way the cart's y axis points. Whole-pixel pen drawing matches pixel art |
| D25 | Past 300 clones, `create clone` silently does nothing | The limit is a cart setting (`stage.cloneLimit`, default 300). Creating one more is a runtime error that stops that script and names the limit and where to change it | A silent no-op is a classic "why aren't my bullets appearing?" bug. The error points at the line |
| D26 | Clones copy "for this sprite only" variables; there's no variable shared by a sprite and its clones | `var` behaves as Scratch's (each clone has its own copy, starting with its parent's value; lists are copied). `shared var` adds one value for a sprite and all its clones | Counting a family (enemies left, next id) otherwise needs a global per sprite |
| D27 | `touching color` sees everything drawn, including the pen layer and backdrop pictures | `touching_color` and `color_touching` sample other sprites' costume pixels, the tile map and the stage background colour, on the CPU. The pen layer isn't included. Colours match on their top bits, as in Scratch | The pen layer only exists on the GPU; reading it back would make results depend on the renderer and on frame timing, and wouldn't work in tests or Node |
| D28 | — | `delta_time()` always reports 1/60: the simulation runs at a fixed 60 ticks a second (D4) | Code ported from variable-frame-rate engines reads naturally and stays deterministic |
| D29 | A checkbox next to each variable shows a monitor on stage | `watch(label, value)` shows `label: value` at the stage's top-left in the pixel font, updated when it runs | Monitors become code, so they're the same in text and blocks and travel with the cart |
| D30 | No `break`, `continue` or dictionaries | `break` leaves the innermost loop and `continue` skips to the next iteration (which still waits a tick, D5); both end their block, like `return` (D12). `dict()` makes a dictionary read and written with `d["key"]` | Common in every text language, and they save awkward flag variables. One index syntax covers lists and dictionaries |
| D31 | Text on stage needs costumes or a speech bubble | `draw_text(text, x, y)` writes on the pen layer in Stitch's own 3×5 pixel font, scaled by pen size, capitals only | The sandboxed stage can't load web fonts, and a pixel font is crisp at any scale and identical in the editor and every exported player |
| D32 | *ask and wait* draws its answer box into the stage; there is no frame counter | `ask(question)` opens an answer field over the bottom of the stage, styled like the speech bubbles rather than Scratch's grey box. Keys typed into it don't start `on key` scripts. `frame_count()` reports the ticks since Run | The stage is a sandboxed page that can't use the editor's UI, and the field is part of the game picture, the same in the editor and every exported player. Scratch has no frame counter; with a fixed 60 ticks a second (D4) one is exact and handy for animation |
